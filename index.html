소개

요구사항을 분석해 설계·구현·연동까지 수행해온 신입 풀스택 개발자 손영선입니다. 유현건설 실무에서는 웹페이지(계측 모니터링)와 어플(현장 조회) 흐름을 각각 구현하며 원시 데이터 수집기 배포, PostgreSQL 적재 파이프라인, 상태 조회 API, 모바일 화면 연동까지 담당했습니다. 스트롱쌀롱은 제가 기획한 목업이 업체에 채택되어 의뢰로 이어진 프로젝트로, 백엔드 전담에서 시작해 프론트까지 맡아 풀스택으로 진행 중입니다.

구현 전 로직과 데이터 흐름을 먼저 정리하고, 장애 상황(네트워크 단절/재부팅)에서도 수집이 이어지도록 자동 재시작·재동기화 구조를 적용했습니다.

입사 후에도 코드 리뷰·배포·모니터링 흐름에 빠르게 적응해, API와 화면을 함께 고려한 유지보수 가능한 풀스택 구현으로 팀에 기여하겠습니다.

스트롱쌀롱

사이트 바로가기 ↗

React/TypeScript + NestJS 기반으로 진행 중인 1:1 PT샵 관리 웹 프로젝트입니다. 역할 기반 인증, 실시간 일정 알림, 회원 상태 시각화를 통합했으며 백엔드에서 시작해 프론트까지 확장해 풀스택으로 진행 중입니다.

상세 내용은 아래에서 프로젝트별로 순서대로 정리했습니다.

프로젝트 상세 - 유현건설 웹페이지

프로젝트 소개: 20년 이상 사용하던 레거시 프로그램 환경에서 메모장(txt) 형태의 원시 계측 데이터를 안정적으로 수집·적재하고, 이를 기반으로 웹 대시보드 조회/상태 확인 기능을 제공한 실무 프로젝트입니다.

실무 맥락: 신규 시스템 연동이 어려운 현장에서, 중단 없는 데이터 수집과 빠른 상태 확인이 핵심이었습니다.

포지션: 백엔드 중심 (API 설계/구현, 수집 파이프라인, 데이터 처리, 프론트 연동 기준 수립)

기술 스택

  • Frontend: Next.js, TypeScript, Tailwind CSS, Recharts
  • Backend: Express, JWT(jsonwebtoken), bcryptjs, Swagger
  • Data: PostgreSQL, ingest 파이프라인, formula_params 기반 계산
  • Infra/Deploy: Render, Vercel, CORS
  • Report: ExcelJS, jsPDF + jspdf-autotable

주요 구현 내용

  • 로그인 시 JWT 토큰을 발급해 세션 기반 접근 흐름을 구성했습니다.
  • bcrypt로 비밀번호를 해시 저장해 계정 정보 보안을 강화했습니다.
  • Bearer 토큰 검증 미들웨어를 공통 적용해 인증 누락을 막았습니다.
  • 역할 기반 권한 분리로 관리자 기능 접근 범위를 제한했습니다.
  • 페이지 진입 시 `/api/auth/me`로 토큰 유효성을 재검증했습니다.
  • 토큰 만료 시 로그인 화면으로 리다이렉트해 세션 상태를 명확히 안내했습니다.
  • 에이전트 전용 ingest API를 `X-API-Key`로 보호해 외부 오호출을 차단했습니다.
  • ingest 처리에 트랜잭션을 적용해 적재 중 오류 발생 시 롤백되도록 구성했습니다.
  • 측정값 저장 시 중복 방지(`ON CONFLICT`)를 적용해 데이터 정합성을 지켰습니다.
  • 측정값 응답을 `raw_value / linear_value / value`로 분리해 검증과 시각화를 쉽게 했습니다.

정보 처리 방식 요약

  • 수집: 에이전트가 원시값 전송 → ingest API 수신
  • 정제: 비정상/중복 데이터 제거, depth 기준 분기
  • 저장: measurements + sensor_status + alarm_events 반영
  • 가공: formula_params로 Linear/Polynomial 계산
  • 조회: 웹에서 필터/기간/depth 조건으로 시각화
  • 활용: 대시보드/알람/리포트(Excel/PDF)까지 연결

프로젝트 상세 - 유현건설 어플

프로젝트 소개: 유현건설 계측 플랫폼의 핵심 모니터링 기능을 모바일 환경에서 빠르게 조회할 수 있도록 Flutter 기반 어플로 이식한 프로젝트입니다.

구현 맥락: 현장 담당자가 데스크톱 환경이 아니어도 센서 상태, 알람, 대시보드 지표를 확인할 수 있어야 했습니다.

주요 구현 내용

  • 로그인/로그아웃/세션복원 흐름을 `AuthController`에서 일원화했습니다.
  • 세션 복원 시 `/api/auth/me`를 호출해 저장 토큰의 유효성을 서버 기준으로 확인했습니다.
  • JWT 토큰을 `flutter_secure_storage`에 저장해 모바일 보안을 강화했습니다.
  • Dio interceptor로 Authorization 헤더를 자동 부착해 인증 누락을 줄였습니다.
  • 권한(`canManage`) 기준으로 읽기 전용/관리 가능 UI를 분리했습니다.
  • 센서/현장/알람/대시보드 API를 도메인별로 나눠 유지보수성을 높였습니다.
  • `depth_criteria`, `correction_params`, `formula_params`를 구조화해 depth별 데이터를 안정적으로 처리했습니다.
  • 수정 API payload를 nullable-safe 방식으로 구성해 의도치 않은 값 덮어쓰기를 방지했습니다.
  • 평면도 업로드를 multipart로 구현해 웹과 동일한 운영 시나리오를 앱에서도 지원했습니다.
  • 목업 모드와 실 API 구조를 분리해 시연 단계에서 실연동 단계로 자연스럽게 전환되도록 설계했습니다.
  • GitHub Releases로 테스트 APK를 패키징하고 QR 코드로 설치 링크를 배포해 현장 테스트 전달 과정을 단순화했습니다.
