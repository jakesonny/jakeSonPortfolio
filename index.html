소개

요구사항을 분석해 설계·구현·연동까지 수행해온 신입 풀스택 개발자 손영선입니다. 유현건설 실무에서는 웹페이지(계측 모니터링)와 어플(현장 조회) 흐름을 각각 구현하며 원시 데이터 수집기 배포, PostgreSQL 적재 파이프라인, 상태 조회 API, 모바일 화면 연동까지 담당했습니다. 스트롱쌀롱은 제가 기획한 목업이 업체에 채택되어 의뢰로 이어진 프로젝트로, 백엔드 전담에서 시작해 프론트까지 맡아 풀스택으로 진행 중입니다.

구현 전 로직과 데이터 흐름을 먼저 정리하고, 장애 상황(네트워크 단절/재부팅)에서도 수집이 이어지도록 자동 재시작·재동기화 구조를 적용했습니다.

입사 후에도 코드 리뷰·배포·모니터링 흐름에 빠르게 적응해, API와 화면을 함께 고려한 유지보수 가능한 풀스택 구현으로 팀에 기여하겠습니다.

프로젝트 상세 - LinkBrief

프로젝트 소개: 링크를 저장하면 서버가 페이지를 크롤링해 본문과 메타데이터를 추출하고, OpenAI Structured Outputs로 요약과 태그를 생성하는 북마크 서비스입니다. 저장 요청은 즉시 응답하고 크롤링·요약은 백그라운드에서 처리하며, 실패해도 에러를 던지는 대신 상태로 남겨 재처리할 수 있게 했습니다.

기술 스택

  • Frontend: Vite, React, TypeScript, Tailwind CSS, Zustand, TanStack Query, Zod
  • Backend: NestJS, Prisma, Passport-JWT, class-validator, Swagger, cheerio, OpenAI API
  • Data/Infra: Neon Postgres, Docker, GitHub Actions, Jest+supertest+Testcontainers

주요 구현 내용

  • 링크 저장을 PENDING 상태로 즉시 응답하고 크롤링·요약을 백그라운드로 분리했습니다.
  • OpenAI Structured Outputs에 Zod 스키마를 적용해 응답 형식을 강제했습니다.
  • 크롤링·LLM 실패를 PENDING→READY/FAILED 상태 머신으로 처리하고 재처리 엔드포인트를 제공했습니다.
  • 소유권 가드로 멀티테넌시를 격리했습니다.
  • 태그 다중 필터·텍스트 검색·커서 페이지네이션을 구현했습니다.
  • Testcontainers로 회원가입부터 소유권 격리까지 통합 테스트로 검증했습니다.
  • Neon 서버리스 환경에서 인터랙티브 트랜잭션이 끊기는 문제를 순차 쓰기로 전환해 해결했습니다.

정보 처리 방식 요약

  • 수집: 링크 저장 요청 → PENDING 상태로 즉시 응답
  • 처리: 백그라운드에서 크롤링 → 본문·메타데이터 추출
  • 가공: OpenAI Structured Outputs로 요약·태그 생성(Zod 스키마 검증)
  • 저장: READY/FAILED 상태로 갱신, 실패 시 재처리 엔드포인트로 재시도
  • 조회: 태그 필터·텍스트 검색·커서 페이지네이션으로 목록 제공

프로젝트 상세 - Pingboard

프로젝트 소개: 게시판에 달린 댓글을 실시간으로 알려주는 알림함입니다. 소켓은 신뢰할 수 없는 채널이라는 전제 아래, 댓글과 알림 저장을 한 트랜잭션으로 묶어 커밋 이후에만 emit하고, 재연결 시에는 REST로 미읽음 목록을 다시 가져와 소켓 유실 여부와 무관하게 데이터가 채워지도록 했습니다.

기술 스택

  • Frontend: Vite, React 19, TypeScript, Tailwind CSS, Zustand, TanStack Query, socket.io-client
  • Backend: NestJS, TypeORM, Passport-JWT, Socket.io, class-validator, Swagger
  • Data/Infra: Neon Postgres, Docker, GitHub Actions, Jest+supertest

주요 구현 내용

  • 소켓 미들웨어에서 JWT 검증 실패 시 핸드셰이크 자체를 거부해 재연결 루프를 방지했습니다.
  • userId 기반 room과 소켓 registry로 멀티탭·멀티기기 동시 브로드캐스트를 구현했습니다.
  • 댓글·알림 저장을 한 트랜잭션으로 묶어 emit 실패가 응답을 막지 않도록 했습니다.
  • 재연결 시 REST 재동기화로 유실 없이 상태를 복구했습니다.
  • 복합 인덱스와 TanStack Query 캐시 단일 소유 원칙으로 중복을 차단했습니다.
  • 서버 프로세스를 실제로 종료·재기동시켜 재동기화까지 검증했습니다.
  • 검수 중 발견한 인증 없는 GET /posts의 이메일 노출 결함을 응답 전용 DTO 분리로 제거했습니다.

정보 처리 방식 요약

  • 수집: 댓글 작성 요청 → 댓글·알림 저장을 한 트랜잭션으로 처리
  • 전달: 커밋 성공 후에만 소켓으로 emit
  • 복구: 재연결 시 REST로 미읽음 알림 목록 재동기화
  • 보호: JWT 핸드셰이크 검증, 응답 전용 DTO로 민감 정보 차단

프로젝트 상세 - SiteScope

프로젝트 소개: 유현건설 현장 실무로 계측 데이터 수집 시스템을 다뤄본 경험을 바탕으로 한 프로젝트입니다. 이후 클라이언트 사정으로 프로젝트가 중단된 뒤, 개인적으로 다시 설계했습니다. 원래는 Next.js·Express 기반이었고, 이번에는 NestJS·Prisma로 새로 구현하면서 기계 인증(HMAC 서명)과 동시 요청 처리를 포트폴리오 수준으로 다듬었습니다.

기술 스택

  • Frontend: Vite, React, TypeScript, Tailwind CSS, Zustand, TanStack Query, 카카오맵 JS SDK
  • Backend: NestJS, Prisma, Passport-JWT, HMAC-SHA256
  • Data/Infra: Neon Postgres, Docker, Jest+supertest+Testcontainers

주요 구현 내용

  • 에이전트 전용 API를 API 키+HMAC-SHA256 서명(상수시간 비교)으로 인증했습니다.
  • 멱등키를 조건부 삽입하는 단일 CTE 쿼리로 중복 적재를 방지하고, 동시 20건 요청 중 정확히 1건만 적재됨을 Testcontainers로 증명했습니다.
  • 기계용 HMAC 인증과 사람용 JWT 인증을 분리된 가드로 공존시켰습니다.
  • 실제 서명 로직을 재사용하는 시뮬레이션 스크립트로 파이프라인을 그대로 통과하는 데모 데이터를 생성했습니다.
  • 현장별 집계의 N+1을 제거하고 복합 인덱스·커서 페이지네이션을 적용했습니다.
  • 카카오맵 SDK 싱글턴 로더로 중복 로드를 방지했습니다.

정보 처리 방식 요약

  • 수집: 현장 에이전트가 계측값 전송 → API 키+HMAC 서명 검증
  • 정제: 멱등키 조건부 삽입 CTE로 중복 요청 제거
  • 저장: 현장·센서별 계측 데이터 적재
  • 가공: 현장별 집계 시 N+1 제거, 복합 인덱스·커서 페이지네이션 적용
  • 조회: 사람 사용자는 JWT로 인증해 웹·카카오맵 화면에서 확인

남은 과제: 서명 범위가 페이로드 전체를 덮지 않는 점, 집계가 500건 표본 캡 기반 근사치인 점을 인지하고 있으며 다음 개선 후보로 남겨뒀습니다.

프로젝트 상세 - 유현건설 어플

프로젝트 소개: 유현건설 계측 플랫폼의 핵심 모니터링 기능을 모바일 환경에서 빠르게 조회할 수 있도록 Flutter 기반 어플로 이식한 프로젝트입니다.

구현 맥락: 현장 담당자가 데스크톱 환경이 아니어도 센서 상태, 알람, 대시보드 지표를 확인할 수 있어야 했습니다.

  • Network: Dio, Interceptor
  • Secure Storage: flutter_secure_storage

진행 형태: 초기에는 백엔드(API·데이터·인증)를 전담했고, 이후 프론트(UI·상태·연동)까지 담당 범위를 넓혀 풀스택으로 마무리했습니다.

핵심 구현 범위

  • 회원/트레이너 권한 분리 인증 및 세션 관리 흐름 구현
  • 일정 이벤트 기반 실시간 알림(WebSocket) 연동
  • 헥사곤 지표 시각화를 위한 평가/스냅샷 데이터 모델 구성

기술 스택

  • Frontend: React, TypeScript, Vite, Recharts
  • Backend: NestJS, TypeORM, JWT, Swagger
  • Database/Infra: PostgreSQL, AWS/Render, WebSocket

프로젝트 공통 역량

  • 요구사항을 기능 단위로 분해하고 API 계약을 먼저 고정한 뒤 화면을 맞추는 구현 방식
  • 인증/권한/운영 안정성(중복 방지, 예외 처리, 만료 처리)을 선행 설계하는 습관
  • 현장 데이터의 수집-정제-저장-가공-조회 흐름을 한 번에 이해하고 연결하는 역량
  • 웹과 앱의 기능 동등성을 체크리스트 기반으로 관리하는 운영형 개발 습관
  • 배포 이후 로그/오류/환경 차이를 재현하고 원인까지 추적해 개선하는 태도

마무리

빠르게 배우고 실행하는 개발자로서, 실무에서 바로 이어질 수 있는 기능 완성과 개선 여지를 함께 찾는 습관을 강점으로 삼고 있습니다.

현장·운영 조건을 전제로 한 풀스택 구현과 협업에 기여하는 개발자가 되겠습니다.
